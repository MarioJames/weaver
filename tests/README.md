# Tests

Tests live in one subdirectory per layer under test, mirroring `src/`:

- `main/` — backend modules under `src/main`
- `cli/` — the CLI under `src/cli`
- `renderer/` — the frontend under `src/renderer`
- `shared/` — cross-boundary contracts and rules under `src/shared`
- `integration/` — cross-layer end-to-end tests (HTTP runtime, standalone bundle, skills install) and the dependency-direction guard (`architecture-boundaries.test.ts`)

`helpers/` holds shared test utilities and `fixtures/` holds data files; neither contains tests. The `test` script in `package.json` discovers tests recursively via the glob `'tests/**/*.test.ts'`, so any file matching `tests/**/*.test.ts` in a subdirectory is picked up automatically — helper and fixture files must therefore never end in `.test.ts`. New tests go in the subdirectory matching the layer they exercise; cross-layer end-to-end cases go in `integration/`.

## Feishu IM: reading route and regression constraints

Before changing the Feishu bridge (`src/main/im/*`, `src/renderer/features/bots/*`, or the IM RPC surface), read `docs/feishu-im.md` as the product contract, then the tests for the boundary being changed:

- `tests/main/im-storage.test.ts` — private settings/Secret keep-clear-replace, structural save/load agreement, CAS and atomic file/revision preservation; inbox claim persistence. Reading v2 maps the single directory to v3's array without writing or advancing revision. Saved directories can be offline or newly protected: disabling the exact ordered baseline list remains possible; changed lists and enabling still undergo full validation.
- `tests/main/im-workspaces.test.ts` and `im-bootstrap-budget.test.ts` — real directory/canonical alias and credential-root boundaries, complete JSON/shell-quoted bootstrap budget using the same `limits.PARENT_TEXT_MAX` at save and startup. Load must not mark an older over-budget configuration corrupt. Budget rejection is atomic and uses the dedicated safe code; the root's immediate start receipt is not owner-host readiness.
- `tests/main/im-channel.test.ts` and `im-card.test.ts` — real SDK dispatcher/header/callback and CardKit ordering/filtering. A mock success cannot prove an SDK write, public delta, cancellation drain or terminal card cleanup occurred.
- `tests/main/im-service.test.ts` and `im-lifecycle.test.ts` — standby startup/rotation, same-chat/user reuse and isolation, busy/queue completion before TTL retirement, authorization/dedup, stop/not-submitted/fatal boundaries and failure recovery. Durable claim IDs/times do not persist queued bodies; normal rotation may continue an admitted waiter, but process restart never replays unknown execution or restores message bodies. Separate Feishu connection from required Agent lifecycle state, including ready with zero phone sessions.
- `tests/main/im-parent-claude.test.ts`, `im-parent-codex.test.ts`, `im-parent-permissions.test.ts` and `im-parent-scope.test.ts` — protocol initialization, public deltas, confirmed terminal cancellation and process scope/permissions. Codex multi-directory permission sources and thread/start results must be provable without changing permission or approval mode; unsupported/null/external profile evidence fails closed instead of claiming external-sandbox support.
- `tests/main/im-parent-host.test.ts` — the actual hidden host runner and framed `parent-host-wire` prepare/submit/not-submitted protocol with fake CLI fixtures, zero warm-up turns, correlated cancellation and continuation. `tests/main/im-parent-host-resources.test.ts` pins exact unit invocation/cgroup/own-Herdr-lane ownership and retained cleanup tombstones; an ACK, missing unit, mock close or substring process match is not proof that all owned resources were released.
- `tests/integration/im-herdr-host.test.ts` — explicit opt-in **real Herdr/systemd with fake model CLI** tests. Read the file's current `WEAVER_IM_HERDR_HOST_TEST`, private `WEAVER_IM_HOST_TEST_ROOT` and built `WEAVER_IM_HOST_TEST_BUNDLE` requirements first; isolate the fixture root, bin/PATH and proof file, preserve other Herdr resources, and verify owned lane/unit/cgroup/journal cleanup. A skipped default run or fake CLI fixture is not evidence of actual model calls or phone delivery. Do not enable these tests merely to make ordinary unit checks look more complete.
- `tests/renderer/renderer-im-settings.test.ts` — independent `/#/bots` page, multi-directory array drafts with Secret/CAS, low preservation, response races and true Agent-vs-network state. Browser verification must exercise the actual numeric DOM value: filling an empty string may leave `30`, so inspect it and use Control+A/Backspace when needed before asserting revision or validation. Also cover already-open WorkspacePicker pointer/keyboard locks, late responses, 390-width long paths, and shared task/schedule consumers. Old [browser evidence](../docs/verification/feishu-im/browser.html) has its own version/scope; a new architecture requires a frozen-version run.
- `tests/integration/im-runtime.test.ts` — real HTTP/RPC/store budget code and actionable static Chinese error with no input/Secret/path leak, unchanged revision/file, unchanged generic safe defaults; HTTP/IPC still close after IM cleanup failure. Every enabled fixture injects fake parent/channel, disables automatic quota/free probes and cannot silently start a real model/Herdr host.
- `tests/cli/cli-web-shutdown.test.ts` — signal/shutdown rejection handling and final exit status; read before changing CLI teardown.

Regression constraints: all related fields save together; polling, navigation, conflicts and uncertain failures keep an active Secret/directory draft until explicit successful save or discard. Keep structural and Secret rules compatible between accepted writes and fresh loads, while live directory/bootstrap checks stay save/start checks so old configurations remain recoverable. Actual project roots/children are independent of the Bot's host journal and must not be cancelled by Bot rotation. Test data uses per-run `mkdtemp` beneath the supplied temporary root and `test.after`/`finally` cleanup, never a task-specific absolute path. Real HTTP/host Unix sockets need a sufficiently short owned temporary path; a path-length setup failure is neither a product behavior failure nor permission to weaken the socket bound. Keep real phone/host/model observations attributed and scoped: final delivery ACK timing is not first delta or phone RTT, and old phone results do not verify a new Herdr build.
