# 飞书 IM 接入说明

状态：用户配置说明，面向 0.6.0。范围是企业飞书（自建应用）+ 手机飞书单聊：你在飞书里直接给 Weaver 的 Bot 发消息，由独立选择的 6 种成熟对话引擎之一承接对话。Weaver 不做外部 completion API 渠道，也不会替你自动申请权限、修改应用配置或绑定账号。

## 支持的能力

- **单聊文本与 post 可读文字**：只支持白名单用户与 Bot 的一对一单聊中的 `text`，以及 `post` 富文本内的可读文字（标题、正文、链接）。输入上限仍为 16KB（按 UTF-8 字节计，超限给固定安全提示而不执行）。`text`/`post` 范围内的空消息、无可读文字（如仅附件/占位符）与超限内容，给固定安全反馈而不执行、不回显原文与凭据；群聊、非白名单用户、机器人消息、非 `text`/`post` 类型以及类型校验不一致的消息直接忽略，不反馈。
- **独立 Bot 配置**：在独立「Bot」页（`/#/bots`）直接选择 6 种对话引擎之一（Claude、Codex、OpenCode、Pi、Grok、Qoder）并填写模型与力度/变体，不依赖父 Agent 或子 Agent profile，不依赖 owner 实例或 worker；「设置」页只保留常规全局选项。对话本身不生成任务卡片，派发的**实际任务**仍走 Weaver 现有调度并进入任务面板。
- **普通问答不建任务**：闲聊、追问、解释说明只在当前 Bot 上下文内回复，不创建逻辑 owner，不调用 `owners.attach`，不写入任务面板。
- **实际工程任务默认同批同项目单 root**：用户明确安排实际工作时，Bot 先识别配置工作空间列表中的目标项目，目标不清先追问，不擅自扩大到列表外；同一批同一项目的多个事项默认建一个 root，再由 owner 按技能拆 child 并行推进，不为同批事项逐项建多个 root 浪费额度。只有独立项目、权限/审批边界不同，或用户明确要求分开时，才拆多个 root。追问、纠正、继续同一件事时，先用 `tasks.get` / `tasks.events` / 任务列表（含分页）查本实例现有任务并复用，不重复派发。派发的**实际任务**仍走 Weaver 现有调度并进入任务面板。先读 agents-weaver 技能入口，入口 Master 的完整行为以 [master-guideline.md](../skills/agents-weaver/references/master-guideline.md) 为单一来源，本节只做摘要，不复制全文。
- **回复以原生流式卡片推进**：父 Agent 的回复用飞书 SDK 的流式卡片实时补写生成进度，完成并收束 SDK 流后，使用同一 CardKit 实体的公开更新接口提交完整正文与选项，序号严格高于该卡此前已发起的操作；不是等全部生成完再一次性发一条消息。同一轮对话里多次公开输出（如工具执行前后）之间以空行分段，同一段内文字原样连接；可靠的段落边界目前仅 Claude、Codex、OpenCode、Pi 按协议事件声明，Grok、Qoder 不按 token 猜段落。正文卡片是 markdown 元素，加粗、列表、代码与段落原样保留。
- **正文卡片只承载下一步选项**：回复卡片上的按钮是 Agent 给出的「下一步选项」。点击一个选项等于把该选项的内容作为**一条新的用户消息**发到同一对话的同一 Agent，不是执行固定的后台操作。新会话/停止这类管理操作在**机器人菜单**里，不在正文卡片上。
- **独立后台常驻 Agent**：启用并保存后启动独立的后台用户服务承载 Agent，不依赖终端标签页；服务的标准输入不决定其生命周期，日志、资源限制与精确 unit/cgroup 归属按后台记录管理，失败的关闭保留 journal 待下次精确回收，历史遗留的旧版 Herdr lane 记录仅沿原路径精确回收，不代表双启动模式。启动按真实顺序进行：原生引擎握手成功后，先读 agents-weaver 技能入口、再按 [master-guideline.md](../skills/agents-weaver/references/master-guideline.md) 完成一次隐藏的身份模型回合初始化，输出固定确认标识后才进入待命，之后保持 hold 等待真实用户；初始化不发飞书消息、不建任务/owner/卡片，但它是一次真实的模型调用。每个新上下文都走同一初始化。相同 chat/user 复用上下文，不同 chat/user 隔离；Bot 自身问答与待命不创建逻辑 owner 或任务。
- **按空闲超时轮转并保持待命**：最后一条成功持久准入的新用户消息后，空闲超过「空闲超时」（默认 30 分钟，可配 1–1440 分钟）即回收旧上下文；正在回复或有已准入队列时，等当前回合与队列结束再回收。确认旧精确 unit/cgroup 已清理（历史遗留的旧版 Herdr lane 记录仅沿原路径精确回收）后，立即重建待命，不等下一条消息才启动。轮转时新准入的消息可等待真实关闭完成，再以**新上下文**继续，不会接回上一段对话。
- **凭据只存在本机**：App Secret 只写入当前实例数据目录内的 `im-settings.json`（权限 `0600`），公共设置只返回 `appSecretConfigured` 布尔值，网页上不回显；open_id 白名单外的消息一律忽略。

## 第一步：在飞书开放平台创建并配置自建应用

全部在[飞书开放平台](https://open.feishu.cn/)后台完成，Weaver 不代做：

1. 创建一个**企业自建应用**，并开启**机器人（Bot）**能力。
2. 申请并开通以下权限：
   - `im:message.p2p_msg:readonly`——读取发给 Bot 的单聊消息；
   - `im:message:send_as_bot`——以 Bot 身份发送回复；
   - `cardkit:card:write`——创建/更新流式卡片与正文选项卡片用。读卡片相关的接口目前不需要；真有需要会随版本说明另行申请，不默认多开权限。
3. 配置事件订阅（**使用长连接接收事件**，不要选 Webhook 回调；Weaver 只在本机运行，没有公网回调地址）：
   - `im.message.receive_v1`——接收单聊 `text` 与 `post` 消息（群聊、非 `text`/`post` 类型按忽略规则处理，`text`/`post` 范围内的空/无可读文字/超限按安全反馈规则处理）；
   - `application.bot.menu_v6`——接收机器人菜单点击事件。
4. 配置卡片回调：在「事件与回调」中选择**新版卡片回调**，订阅 `card.action.trigger`（正文选项按钮与卡片更新的回传走它），同样使用长连接。
5. 发布一个**可用版本**：权限、事件与回调的变更都要随版本发布才对企业内生效；未发布的版本收不到消息、菜单也不生效。

参考文档（官方）：

- 事件订阅与长连接配置：[配置事件订阅](https://open.feishu.cn/document/ukTMukTMukTM/uYDNxYjL2QTM24iN0EjN/event-subscription-configure-)
- 服务端 SDK（Weaver 使用其长连接客户端）：[larksuite/node-sdk](https://github.com/larksuite/node-sdk)

## 第二步：在 Weaver 独立 Bot 页面填写配置

打开主导航「Bot」（`/#/bots`，可直接访问或刷新），填写后点「保存修改」（字段一起保存，失败时草稿保留）。「设置」页保留常规全局选项，Bot 配置在独立页面管理：

| 字段 | 填什么 |
| --- | --- |
| App ID | 自建应用的 App ID，`cli_` 加 16 位十六进制字符（如 `cli_a1b2c3d4e5f6a7b8`）。 |
| App Secret | 应用密钥。只在保存时提交，之后不回显；留空保存表示保持已存值不变，粘贴新值即覆盖，「清除已保存」在保存时删除它。 |
| open_id 白名单 | 允许对话的飞书用户 open_id，每行一个，必须以 `ou_` 开头。第一版建议只填你自己。 |
| 引擎 | 6 种对话引擎（Claude、Codex、OpenCode、Pi、Grok、Qoder）按需选择，直接控制 Bot 聊天，不用创建父 Agent profile，不覆盖全局 owner/worker 配置或调度权重；未启用/暂不支持的引擎不可选。 |
| 模型 | 从所选引擎的模型列表中选，或直接填写模型名。列表加载失败/为空也可手填；切换引擎会清空旧模型，需重新明确选择，不自动替换为另一个模型。OpenCode 没有固定力度档，按所填模型接受的 variant 填写。 |
| 思考力度 | 按引擎支持范围选择，默认 medium。OpenCode 填该模型接受的 variant（最多 32 字符，字母数字开头）。换引擎时仍合法的力度保留，否则回到 medium。 |
| 工作空间 | 浏览 Weaver 所在机器的目录并添加到列表，可逐项移除，最多 32 个。Bot 可访问全部已配项目目录，按任务目标选择，不是每个会话只能选一个。 |
| 空闲超时（分钟） | 单聊会话的空闲结束时间，1–1440 分钟，默认 30。 |

打开「启用飞书 IM」并保存后，Weaver 通过长连接接入飞书并启动 Agent。「连接状态」只表示飞书网络状态与会话数；独立「Agent 状态」显示未启动、启动中、待命、回复中、结束中或启动异常，网络「已连接」不等于 Agent 已就绪。尚无手机会话时也可待命（活跃会话数为 0）。「刷新状态」只读刷新；「重建连接与会话」在启用且已保存配置后用于显式完整重建，失败不自动重放已执行或结果不明的输入。引擎、模型、力度、工作空间或白名单变化只结束旧上下文并重建 Agent，健康且凭据相同的飞书连接保持；仅空闲时长变化且通道健康时只重算回收时间，不重建。关闭开关并保存会断开连接并回收手机对话 host；已派发的项目任务继续运行。

保存使用乐观锁：配置被其他地方（另一标签页或后台工具）改动过时，保存会报冲突并保留你的输入；页面横幅提供「放弃修改并载入最新」，确认后用控制面当前配置替换这些输入。

工作空间必须是已存在的绝对目录，每条最多 2000 字符；不接受控制字符、重复目录或指向同一真实目录的多个别名，也不允许配置 CLI 凭据目录。保存时按真实路径校验，并在完整目录列表、实际实例路径的 shell 转义、JSON 转义和固定引导文本生成后，检查 16000 字符的 Agent 启动预算。总预算超限会明确提示减少工作空间或缩短实例路径，不截断目录；保存失败不改变文件或修订。完整有序目录列表会原样传给 Bot 启动引导，首个目录作为进程 cwd；目录列表不代表操作系统沙箱，Bot 的本机权限仍沿用各引擎原生 CLI 权限策略，不存在 bypass 开关。

多工作空间的引擎边界（以各引擎原生能力为准）：Claude、Codex、Qoder 原生支持多 root（Claude/Qoder 以 `--add-dir` 透传其余目录，Codex 在已验证的权限/审批来源下透传 `writable_roots` 并回读确认，缺来源或不一致时拒绝）；Grok 无多 root 能力，首个目录作为 cwd 与 ACP workspace，其余目录只留在引导文本中按 Grok 原生本地权限访问，不创建链接视图、不静默丢弃；Pi 无 `--add-dir` 与内置沙箱，首个目录为 cwd，其余目录留在引导文本中按用户原生 Pi 工具/扩展权限以绝对路径访问，不加 `--approve`，不禁用扩展。需要交互审批但手机端无批准控件时，对应工具请求会明确拒绝并在对话中说明，不默认批准，也不是所有工具一概禁用。

保存过的目录后来移动或失效，仍可保留原有完整有序列表、仅关闭 Bot；改动列表或重新启用必须重新通过目录和预算检查。引擎、模型、力度或完整有序目录列表变化后，旧 host 回收完才重建；未经证明的清理失败会显示异常，不假装已待命。已有 Secret、模型和 low 等力度不会因迁移被重置。

「重建连接与会话」会结束当前上下文并按最新已保存配置完整重建（含通道）；引擎、模型、力度、工作空间或白名单变化只结束旧上下文并重建 Agent，健康且凭据相同的飞书连接保持；凭据、启停变化或网络故障时重建通道。健康保存（配置无实质变化）或仅调整空闲时长时不重建，只重算回收时间。空闲超时到期、配置实质改变、等待超时或显式重建才会结束旧上下文。空闲时已有已准入排队消息，等本轮与准入队列安全收束、确认关闭后再按新上下文继续。

## 你的 open_id

open_id 是飞书用户在本应用内的标识，**Weaver 不做自动绑定**，需要你从官方渠道取值后粘贴进白名单。官方获取方式见开放平台文档（如通过通讯录 API 查询、或应用后台/调试工具查看），以官方说明为准：

- 获取与说明入口：[如何获取 user_id / open_id / union_id](https://open.feishu.cn/document/home/user-identity-introduction/how-to-get)

## 机器人菜单：新建会话 / 查看状态 / 停止回复

菜单项由你在飞书开放平台后台手动添加，Weaver 不代为修改真实应用的菜单。在应用后台给机器人添加菜单项，每项填入下表对应的 event_key；点击后 Weaver 收到 `application.bot.menu_v6` 事件（与消息同走长连接）：

| 菜单名称示例 | event_key | 行为 |
| --- | --- | --- |
| 新建会话 | `new_session` | 清空当前对话的上下文与排队的消息，从零开始；已派发的任务独立，照常在任务面板继续，不受清理影响。 |
| 查看状态 | `status` | 返回当前对话正在回复或空闲、排队条数和只读任务数量摘要；连接与最近消息/回复时间在 Bot 页查看，已派发任务详情以任务面板为准。 |
| 停止回复 | `stop` | 只停止当时正在生成的那一条回复：对话上下文与已准入的排队消息保留；当前回合与流式发送队列收束后，排队消息自动按顺序继续，不需要再发消息唤醒；没有正在生成的回复时，只提示「当前没有正在生成的回复」，不会更换会话。已派发的任务仍按任务面板管理。 |

菜单数量与名称字符上限以控制台限制为准；没有配置的菜单项不存在，Weaver 不会创建或隐藏它们。菜单事件与权限、事件一样需要随版本发布。

## 正文选项卡片与回调校验

- 一张回复卡片里的按钮都是该 Agent 给出的**下一步选项**：点击后把选项内容作为一条新用户消息发到同一对话（可以继续追问是真对话语义），Weaver 不把这些按钮解释成固定命令。
- 卡片回调由 Weaver 校验来源才处理：发起用户是否在白名单内、卡片是否属于当前对话、action 是否在有效期内；重复点击/过期回调不会重复投递。回调只返回即时提示（toast），不返回替换卡片；服务端整张选择卡仅消费一次。卡片回调用长连接 `card.action.trigger`，同样需要随版本发布。
- 对话中的操作沿用各引擎已有的本机权限配置；需要新的本机授权但手机端没有批准控件、无法启动交互审批时，该步骤会**明确拒绝**并在对话中说明，不会为对话自动扩大本机权限，也不是所有工具一概禁用：已在本地配置中允许的工具照常可用。

## 多实例注意：同一应用只连一个 Weaver

同一个自建应用的凭据同时被多个 Weaver 实例（或多个服务）用于长连接时，飞书会把消息**分摊投递**给各连接，单个实例只能看到一部分消息。一个应用凭据只配一个正在启用飞书 IM 的 Weaver 实例；要多机使用，请在飞书后台为每个实例建独立应用。

## 实际项目任务与消息持久性

用户明确安排实际工作时，Bot 先识别配置工作空间列表中的目标项目；目标不清楚就先询问，不擅自扩大到列表外目录。Bot 作为入口 Master 先读 agents-weaver 技能入口，Master 行为以 [master-guideline.md](../skills/agents-weaver/references/master-guideline.md) 为单一来源，不复制全文，再读取现有策略，选择已启用、可用、未阻断且可启动为 owner host 的现有 owner profile（`tasks.start` 当前要求 claude 或 codex owner；Master 的对话引擎不限制执行 owner 的选择，可跨引擎，例如 OpenCode 对话可选已有可用的 `codex_owner`），通过 `tasks.create(ownerProfileId, workspace)` 创建真实 root（workspace 为列表中选定的绝对项目目录，不省略、不沿用 Bot 自身 cwd）。同一批同一项目的多个事项默认只建一个 root，由 owner 拆 child；独立项目、权限/审批边界不同或用户明确要求分开时才建多个 root；追问/纠正/继续先查现有任务并复用，不重复派发。再调用 `tasks.start`。启动 ACK 仅表示请求已受理；随后通过 `tasks.get` / `tasks.events` 观察真实 `ownerHost` 或启动失败，才报告主 Agent 已启动或失败。对应 Herdr 主 Agent 执行拆分、Weaver 派发和验收，真实 root/child 正常进入任务面板；Bot 不自身 `owners.attach`，也不为普通问答建隐藏任务。

持久化的 inbox claim 仅包含消息标识和时间，不保存排队正文；排队正文只在进程内存中。正常 idle 轮转期间已准入并等待关闭的消息可续到新上下文；服务重启不会恢复或重放这些正文。已派发项目 root 不属于 Bot host 的清理 journal，Bot 关闭、换配置或轮转不取消它们。

## 已验证范围与待验证（产品说明口径）

- 历史基线仅作范围参考：此前版本已完成的租户 token 与机器人信息只读查询、官方 SDK 长连接验证、双引擎多轮与中断后续聊等，其范围以已有历史报告为准（例如 `docs/verification/` 下的既有飞书与定时任务报告），不等于 0.6.0 六引擎已上线。
- 仍需逐项验证的实链：手机端流式卡片实时推进、正文选项点击、机器人菜单三类事件、多项目手机派发，以及手机端 `post` 富文本的真实收发。需按上述权限/事件/回调/菜单配置逐项验证，不将普通文本最终回复视为这些链路通过，不声称已上线或手机实链通过。
- 仅单聊 `text` 与 `post` 可读文字进入对话；群聊、非白名单、机器人消息、非 `text`/`post` 类型与类型校验不一致的消息直接忽略；`text`/`post` 范围内的空/无可读文字/超限内容给固定安全反馈而不执行。长对话的重要结论应写回任务或文件，不依赖跨轮转保留记忆。

## 授权检查点与依赖限制

白名单、Bot 所选引擎可用性、引擎级与当前模型级 block 在新消息入站、实际回合开始和出站请求前复验；常规 RPC 返回后也会 reconcile。父/子 Agent profile 的变更或仅针对其他 worker 的阻断不改变独立 Bot 对话路由。授权或有效 engine/model/effort/完整有序 workspaces 指纹变化后，旧代在这些检查点被隔离并回收。静默且没有增量/出站的长回合，不保证因所有内部自动策略变化瞬时停止；此处没有额外策略 observer。重复消息不刷新最后用户时间，等待旧父关闭的消息以最初成功准入时刻计算 idle，不以关闭完成时刻延后。

正常在线 stop/new_session 在旧 producer 与 SDK 发送队列收束后，最多用 5 秒对刚发出的同一 CardKit 实体做一次固定“已停止”终态清理（关闭流式、无选项），超时会中止该 HTTP 请求。此清理是 best effort，不恢复旧 Agent 文字；禁用、换凭据或撤权后禁止旧代外发，网络不可达时也不能保证远端卡片立即改变外观。连接或投递失败不自动重跑已执行输入，也不把未确认投递记为成功回复。

Codex 多目录会核对已有配置的有效权限/审批来源与实际启动结果，不能证明来源、值为 null 或无法验证的外部 profile 会安全拒绝并显示 Agent 异常，不自动提权。可证明的 read-only、workspace-write、danger-full-access 来源保持既有约束；不宣称操作系统沙箱，多目录能力以各引擎原生实现为准，单目录继续沿既有路径。

官方 `@larksuite/channel@0.7.1` 在尚未 ready 时调用 disconnect 会跳过内部 safety.dispose；Weaver 会中止本代 HTTP、关闭 WS 并收束迟到连接，但 SDK 的 unref sweeper 小型计时器对象仍可能残留。这些对象不会单独阻止进程退出，不等于活跃 WS/父 Agent 残留；当前没有 fork 或重写 SDK，也不宣称零内部 timer。上述 SDK/HTTP 边界有隔离测试，手机端流式、按钮和菜单实链仍未验收。

已有 v1 私有设置由本次维护执行受保护的一次性转换；这不是日常用户操作流程，网页无需迁移按钮，也不要求用户编辑私有文件。

已有 v2 私有文件在读取时将唯一 workspace 无损映射为 workspaces 数组，文件字节与修订不变；下一次成功 CAS 保存原子写成 v3 并递增修订。RPC 只使用 workspaces 数组，不保留旧 workspace 投影；私有 Secret、既有引擎/模型/力度完整保留，不要求用户手工编辑配置文件。
