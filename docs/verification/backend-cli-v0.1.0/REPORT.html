接口与恢复行为

  • workers.spawn、运行中 native 的 tasks.get 与 tasks.retry 返回规范 next。wait 给等待命令；native 给完整 model、effort、prompt 与完成命令，CLI text 同样保留这些内容。
  • 全局 worker 路由比较 (running+cancelling+1)/weight，平手按更高权重、再按列表顺序；权重 0 不可派发。容量按 durable owner 实例计算，身份为 profileId+name+session，不设 profile/global 容量帽。
  • engines.health 是不含 history 的摘要；engines.penalty 是含保留 history 的完整单引擎记录。engines.unblock 清所选精确引擎的全部阻断，返回 engine、wasBlocked、cleared、retainedHistory、otherEngines；wasBlocked 仅指原自有 stall 阻断。
  • 重试先完成全部预检，再取消、克隆、冻结新包并派发；冻结原任务仍消耗新包，1000 包即拒绝。failed/cancelled/cancelling 链引擎排除，completed 引擎可选；无剩余候选在取消／创建前拒绝，real 不回退 mock。
  • 静默与 CPU 连续空闲均满 5 分钟、同引擎至少 2 任务才触发惩罚。L1/L2 到点需成功恢复探测；L3 需连续 3 次成功。自动恢复只删自有 stall block，手动解除才清所选引擎全部来源。history 全局 50 条、每条 50 个任务 ID，保留真实 taskCount；损坏状态回退不静默放行已有 block。
  • owner 启动异步等待最终响应，无 pending/jobs API。在途 receipt 防重复启动，同 task+epoch 互斥；完成时读取新任务状态，旧 binding／drain 清理本次精确资源。仅完整验证的显式启动请求获得固定 210000 ms，普通／半帧／坏格式／未认证请求仍为 15000 ms，CLI 更短显式等待受尊重。
