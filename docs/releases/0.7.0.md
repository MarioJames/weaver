# Weaver 0.7.0

本版重点是让升级和长时间任务更可靠：服务重启不再打断本版启动的任务 worker，CLI 在服务短暂不可用时自动重连；长任务不再因记录量或命令运行被误判失败。另新增 DeepSeek Harness 引擎，并更新 Bot 页面、定时任务、重试与临时目录清理。

## 新功能

- **服务重启不打断任务**：本版启动的真实 CLI worker 改为写独立日志文件，不再依赖服务进程管道。停止或升级服务后 worker 继续运行，新服务启动时按持久记录接回并继续收集结果；`weaver server stop` 不再因运行中 worker 拒绝，需要一并取消时使用 `--cancel-workers`。自动接回仅适用于本版创建且带持久启动记录的运行。
- **CLI 自动重连**：服务重启期间，`tasks get`、`wait`、`watch`、`events` 和 `health` 会在宽限期内自动重连，重连进度只写 stderr，stdout 仍保持一份 JSON 信封；超过宽限期才按实际错误失败，变更类命令不会自动重试。
- **DeepSeek Harness（dsh）**：新增 dsh 引擎，以无头模式运行，提示词走 stdin，工作目录为任务工作区；提供 `deepseek-flash`、`deepseek-v4-pro` 和 `off/low/high/max` 力度。密钥由 dsh 自己的凭据存储或 `DEEPSEEK_API_KEY` 提供，Weaver 不读取、不保存。默认禁用，需要在策略中显式启用。
- **定时任务选择执行者与目录**：Agent 定时任务可选择父 Agent（owner）或 worker profile 执行，模型与力度取所选 profile 的当前值；工作目录可留空，留空时使用该定时任务自己的独立中性目录，不再回退调用方或服务目录。
- **临时目录自动清理**：服务启动时及之后每 6 小时清理系统临时目录中 Weaver 自有前缀、超过 24 小时且无活动进程占用的目录；只处理当前用户所有、允许前缀的真实目录，不跟随符号链接，也不会删除普通 `weaver-` 任务目录。可在策略 `janitor` 中调整或关闭，也可用 `weaver janitor status`、`weaver janitor sweep --dry-run` 和 `weaver janitor sweep` 查看或立即执行。

## 改进

- **长任务不再因记录量失败**：去掉 worker 记录累计条数和总量的硬上限；时间线保留最早 50 条与最近 400 条过程记录，中间用一条省略标记说明，结果、产物和失败记录不受影响。产物超过 20 个或 mock 进程输出超过 32 KiB 时，任务不再判失败，超出部分不会保留，并给出说明。
- **卡住判定更准确**：CPU 活跃度合并 worker scope 与完整进程树（含被 systemd scope 移出的子孙）；命令运行期间显示「命令运行中」，不会因模型静默而误判卡住。新增 `herdr.max_command_minutes`（默认 30 分钟）：单条命令超过后 health 报告 `command_timeout` 并让 `tasks wait` 提前返回，Weaver 不会自动杀命令。取消或结束时也会精确清理逃逸到其他 systemd scope 的子进程。
- **等待跟随配置**：`tasks wait/watch` 省略 `--for` 时按 `herdr.max_wait_minutes × 60` 秒等待，不再固定压到 600 秒；显式 `--for` 接受任意不小于 1 的整数秒。该设置只是父 Agent 的查看间隔，不是执行时限，Weaver 不会因此停止 worker。
- **Bot 页与消息格式**：Bot 页按渠道分标签，目前包含飞书；设置项改为响应式两列布局，窄屏自动堆叠。飞书回复改用 Markdown 渲染，加粗、列表和代码保留，段落按引擎提供的可靠事件分段而不按 token 猜测；单聊接收范围增加 `post` 富文本中的可读文字，仍只处理白名单用户的一对一 `text`/`post`，其他类型忽略。
- **重试按 worker 排除**：`tasks retry` 只排除失败、取消或取消中的 worker，同引擎的其他 worker 仍可接手；供应商限流也只排除当前 worker，不再整台引擎跳过。最近一次被拒验收的审查意见会带入重试说明（超长时截断），要求逐条处理。
- **任务取代**：设计变更时，父 Agent 可将已取消的子任务标记为被取代并指向接手的子任务；根任务完成校验不再把这部分已作废的叶子计为阻塞。

## 升级说明

- **首次从旧版升级必须先排空**：旧版启动的 worker 没有本版的持久启动记录，无法在服务重启后接回。请等真实 worker 全部结束（或先结束相关任务）后再停服、替换程序并启动；不要在有运行中真实 worker 时直接停服升级。升级到本版后，后续服务重启可以直接进行，接回范围仍仅限本版创建且带持久记录的运行。
- **保留现有数据**：升级沿用现有配置、凭据、工作空间与历史，不需要重新填写凭据或清空任务；不要删除或重建数据库。
- **升级前备份**：相对最新公开版，本版将数据库 schema 从 11 升到 12，只新增临时目录清理历史表；旧版无法打开 schema 12 的数据库。升级前请用 SQLite 的 backup API 备份 `weaver.db`，或完全停止服务后再复制数据库文件；不要在服务或其他进程仍写入时直接拷贝。
- **回滚**：先在新版上排空任务，或执行 `weaver server stop --cancel-workers` 并确认没有运行中的 worker，再还原升级前的备份，之后才能运行旧版。不要绕过备份直接用旧版打开已升级的数据库。
- **飞书与定时任务不在此次接回范围**：飞书对话的上下文、排队消息和进行中的回合不保证随服务重启继续；定时任务的进行中运行也不保证跨重启继续，重启时会先核实并结束旧运行，错过的触发最多合并执行一次，不会逐次补跑。重要结论请写入任务或文件，不要依赖对话上下文或运行内存保留。
