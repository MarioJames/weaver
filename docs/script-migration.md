# agents-cooperation script migration inventory

Source of provenance: the real Apache-2.0 upstream `skill-foundry` revision `61989b1`, `skills/agents-cooperation/` ([upstream tree](https://github.com/MarioJames/skill-foundry/tree/61989b11a5d0565d2a6630833e64a2d73769a947/skills/agents-cooperation)). Weaver itself builds the public skill `skills/weaver` in this repository; the old upstream path is kept only as a historical attribution, not an installable or runnable skill here. This is a **bounded, partial code migration** into Node control-plane code, not a claim that every old script is migrated. No upstream files were changed and no old executable was run. See also the provenance note in [skills/weaver/references/provenance.md](../skills/weaver/references/provenance.md).

## Script-by-script disposition

| Source file | Disposition | Weaver implementation / reason |
|---|---|---|
| `scripts/agents-config.ts`: validation, EFFORTS, availability, active blocks, release-time parsing, worker selection | Migrated/adapted (class tags, domain tags and engine pins later removed; selection is weight-only) | `src/main/policy/routing.ts`: same structural and cross-reference rules; mechanical → routine class tiers, judgment domain preference, tag/native/order sequence, explicit-worker warning with weight-0 and `only_engine` exclusions, skipped diagnostics and peer suggestion. Extensions beyond upstream: integer `worker_weights` (0..1000, default 100) within tiers, `only_engine` hard pin, and preview reuse as the admission resolve function (`policy preview` vs `workers spawn`, same resolve). |
| `scripts/agents-config.ts`: CLI parsing, show/validate/status/block/unblock | Replaced | The `weaver` CLI (`src/cli/main.ts`) exposes `policy get/validate/save/preview` and `engines scan/set-enabled` as method-wrapped RPC verbs over the shared Unix-socket/loopback handler; `PolicyStore` validates, atomically saves with revision checks, and the web Settings page edits through the same layer. No Bun CLI or global-path discovery. |
| `scripts/agents-config.ts`: interactive argv, native tool parameters, peer launch, opencode remembered-variant reads, web launcher | Intentionally not ported | Real engines run through fixed `src/main/adapters/cli/argv.ts` builders (shell:false, fixed executable names) with native auth reused in place. Each builder carries that engine's own non-interactive approval flags (`opencode --auto`, `pi --approve`, `grok --permission-mode bypassPermissions`); these configure each CLI's own approval behavior and are not a Weaver sandbox claim — no OS/process isolation beyond the owned launch scope is asserted. No hidden sessions, host-home reads, or automatic peer launch. Peer suggestion stays advisory text. |
| `scripts/agents-runtime.ts` | Retired as worker runtime; not ported | `TaskManager` (`src/main/manager.ts`) owns worker child liveness with a SIGTERM→SIGKILL stop and one standard JSONL record supervisor for mock and real engines alike: mock runs the bundled script, real launches run through `RoutingWorkerAdapter` (`startCliAgent`, owned scope units). Old run/lane/session/GC/reconciliation logic is not copied or enabled; there is no second daemon to operate. |
| `scripts/lib/json-schema.ts` | Migrated | `src/main/policy/json-schema.ts`, same supported JSON Schema subset and prototype-safe property/ref handling, with upstream attribution. |
| `scripts/lib/state-db.ts` | Replaced | `PolicyStore` stores config and blocks in `policy.v1.json` (≤256 KiB, ≤500 blocks, timestamp-validated absolute blocks, duplicate block rejection, engine/model identity, expiration filtering, manual removal). App task history lives in the store behind `src/main/store.ts`. No SQLite import, run/lane tables, or historical takeover. |
| `scripts/lib/external-call.ts` | Not migrated | The old Herdr command launcher is incompatible with app-owned bounded workers; no external-command surface exists. |
| `scripts/lib/process-identity.ts` | Not migrated | `/proc` identity scanning was never a portable containment proof. Real launches are wrapped in an owned scope unit; the control plane restarts without reconnecting to old PIDs. |
| `scripts/lib/session-evidence.ts` | Not migrated | Old hidden-session cleanup has no equivalent in the current system; Weaver owns only the processes it launches. |
| `scripts/lib/runtime-events.ts` | Not migrated | SQL triggers referenced retired run/lane tables. Event history lives inside task records with retained event IDs and `CURSOR_EXPIRED` cursors; there is no global durable event bus. |

## Related assets, code and tests

- `assets/config.schema.json` and `config.default.json` are bundled under `src/main/policy/`. The provider/model vocabulary stayed the upstream baseline plus the local machines (e.g. `gpt-6.1-sol`, `grok-4.7`, `glm-5.3-flash`, `opencode/glm-5.3-flash-free`); nonempty model strings and example/disabled templates are not a catalog lookup or installation proof. `herdr.max_wait_minutes` is now an enforced real-execution timeout (1–1440 minutes), not a compatibility-only field. `chatgpt_review` stays a routing-policy preference switch (`preview.chatgptReview`); no external review integration is wired.
- The engine allowlist, readiness facts and `EXECUTION_BOUNDARY` come from `src/shared/engines.ts`: probe = PATH + `--version` only, enablement authority = policy, adapter status `real` (opencode/pi/grok/codex) / `deferred` (claude) / `not_implemented` (qodercli/gemini), and enabled engines never create roles automatically.
- `web/server.ts`, `web/launch.ts`, `web/lib/*.ts` are not bundled. The current web stack is the rendered React UI served by `weaver web` on loopback plus the shared RPC layer; settings editing and saved-route preview are policy operations, not the old board writer.
- `tests/agents-config.test.ts` behavior is covered by the Node tests over the pure policy module (structural/semantic validation, effort sets, prototype safety, routing order/classes/tags/weights, explicit selection with zero-weight and pin exclusions, advisory peers, blocks/expiry, release parsing, persistence/revision conflicts, invalid input retention, preview capacity). Tests run against app interfaces, not old Bun commands.
- Old runtime/state-db/web tests are not claimed ported: their session/SQLite/HTTP contracts do not exist in this system. Current test/typecheck/build evidence is linked from [VERIFICATION.md](../VERIFICATION.md); the migration-time `npm run check` results recorded earlier in this document were a point-in-time check of a different feature set and are not a current acceptance claim.

## Boundary notes

- Preview responses keep `dispatch:"preview"` and `execution:"disabled"`; preview includes owner `max_parallel` plus a capacity calculation from the caller-supplied `runningCount`. Admission and dispatch are the same resolve function, but a failing preview does not start anything. Mock execution is an explicit `provider:"mock-jsonl"` request and is recorded as mock; real dispatches record the frozen route plus requested engine/model/effort and observed evidence.
- Policy documents are validated whole and saved with revision checks; conflicting revisions fail and invalid input preserves the previous file. Store caps and durability semantics (fsync + rename, no directory fsync, durable intent before effect) are described in [architecture](architecture.md).
- The skill (`skills/agents-weaver`) carries collaboration principles and current CLI guidance only; it does not run Herdr scheduling, or any hidden-session machinery routed through Weaver.
