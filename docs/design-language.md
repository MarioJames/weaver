# Weaver 设计语言「经纬」

状态：现行规范，2026-10-26。适用于 `src/renderer` 全部页面。工程写法（StyleX、依赖入口、Provider、构建）仍以 [ui-style.md](ui-style.md) 为准；本文定义产品层面的信息架构、交互模型与视觉规则，两者冲突时以本文为准并同步修改 ui-style.md。

## 0. 为什么重做

Weaver 起步时只有「任务看板 + 几个配置页」，交互按「一个页面一种对象、一张卡片一条记录」设计。现在的真实规模与关系已经超出这个模型：

- 共享实例里有 1300+ 个任务、200+ 个父 Agent 实例。绝大多数任务挂在宿主会话（Claude Code / Codex 里登记的父 Agent）名下，少数来自网页发起的根任务。看板只显示子任务，按状态分列，**父 Agent 这一层只能靠筛选芯片间接看到**；根任务、父 Agent 的进度汇报（`ownerReport`）在界面上完全缺席。
- 筛选区五行芯片占掉首屏三分之一；四列看板常有两三列为空；详情抽屉七个标签页，概览几乎是空的。
- 配置页各写各的：渠道是带内联开关的宽列表 + 弹窗编辑，父/子 Agent 是主从分栏 + 页级保存（但开关和删除又是即时提交），Bot 的保存按钮在最后一行，设置是三栏表格逐项即存。同一类操作有五种保存模型。
- 渠道 → Agent → 任务之间的引用只能读文字，不能跳转；选中的任务、渠道、Agent 不进 URL，刷新即丢失。
- 术语漂移：推理强度 / 思考力度，工作目录 / 目标项目目录 / 工作空间 / 工作区，调度主引擎 / 父 Agent。

「经纬」的目标：让用户一眼看到**谁在做什么、哪里需要我**，并在三次点击内到达任何一条记录的细节。

## 1. 设计原则

1. **以会话为经，以任务为纬。** 父 Agent 会话是工作的主轴，子 Agent 任务挂在会话下面。任何任务都能回到它的会话，任何会话都能展开它的任务。
2. **注意力优先。** 排序、默认视图和导航角标都先回答「哪里需要我」：停滞、失败、需修改、验收等待过久的排在最前；正常进行中的其次；已结束的默认收起。
3. **一处一事。** 同一事实只出现在一个固定位置。关系用链接表达，不复制内容；已在组头或上下文里出现的信息不在行内重复。
4. **地址即状态。** 当前页面、选中的会话 / 任务 / 资源都写进 URL hash，刷新、后退、复制链接都回到同一处。
5. **渐进披露。** 默认只显示做决定所需的信息；解释文字收进 `TitleWithTips` 的提示，高级字段收进可折叠区；长说明不出现在页面正文里。
6. **两种保存模型，不多不少。** 结构化配置走「草稿 + 底部保存条」；开关和单步动作即时生效并就地反馈。见 §6。
7. **安静的界面，响亮的状态。** 表面一律中性灰阶，颜色只留给状态语义和唯一的主操作。

## 2. 术语表

界面文案只用左列；CLI、英文文档和代码标识符保持原名。

| 界面用语 | 含义 | 不再使用 |
| --- | --- | --- |
| 会话 | 一个父 Agent 实例（`owners` 表的一行）及其派发的全部任务；网页发起的根任务也是一个会话 | 实例、宿主（作名词时） |
| 会话目标 | 网页发起的根任务（`executionRole:'owner'` 且无 `parentTaskId`）的目标与验收标准 | 根任务、父任务 |
| 任务 | 一个交给子 Agent 执行的工作包 | 子任务（行内标签除外） |
| 父 Agent | 策略里的 owner profile（父 Agent 页）或会话的执行者 | 负责人、主 Agent、调度主引擎、Master |
| 子 Agent | 策略里的 worker profile 或任务的执行者 | 工作代理、worker |
| 账号与渠道 / 渠道 | 官方订阅账号或 API 渠道；页面名用「账号与渠道」，字段名用「账号或渠道」 | — |
| 推理强度 | effort | 思考力度 |
| 工作目录 | 任务、会话、定时任务、Bot 使用的绝对路径 | 目标项目目录、工作空间、工作区、宿主工作区 |
| 进度汇报 | 父 Agent 用 `tasks report` 推送的 `ownerReport` | — |
| 保存 / 放弃修改 | 草稿提交 / 丢弃 | 保存修改、保存配置、暂存并关闭 |
| 刷新 | 重新读取当前数据 | 重新读取、刷新状态、重试读取 |
| 排队中 | 任务等待调度（`scheduled`） | 与「定时任务」混用 |

## 3. 信息架构

### 3.1 导航

`ConsoleNav` 分组，所有分组默认展开：

| 分组 | 页面 | hash | 角标 |
| --- | --- | --- | --- |
| 工作 | 工作台 | `#/tasks` | 需关注的任务数（§5.2 的关注集合） |
| | 定时任务 | `#/schedules` | — |
| 编排 | 父 Agent | `#/owners` | 已暂停的父 Agent 数 |
| | 子 Agent | `#/workers` | 已暂停的子 Agent 数 |
| | 账号与渠道 | `#/channels` | — |
| 接入 | Bot | `#/bots` | — |
| 系统 | 设置 | `#/settings` | — |

角标只计「需要人处理」的数，为 0 时不显示。品牌位文案为「Weaver」。

### 3.2 路由

hash 路由，格式固定，解析与生成只在 `src/renderer/app/router.ts` 一处：

```
#/tasks                              工作台，看板视图（默认）
#/tasks/t/<taskId>                   看板中打开任务（检查器覆盖）
#/tasks/s                            会话视图，未选中
#/tasks/s/<sessionKey>               选中会话
#/tasks/s/<sessionKey>/t/<taskId>    选中会话中的任务（右侧检查器打开）
#/tasks/all                          工作台，全部任务表
#/tasks/all/t/<taskId>               全部任务表中打开任务
#/schedules[/<scheduleId>]
#/owners[/<profileId>]
#/workers[/<profileId>]
#/channels[/<channelId>]
#/bots
#/settings
```

- `sessionKey` 由 `sessionKeyOf(task)` 唯一决定：属于网页根任务的（自身是根任务，或 `parentTaskId` 指向根任务）为 `r-<根任务 id>`——接续换了父 Agent 实例也仍是同一会话；其余有 `ownerId` 的为 `o-<ownerId>`；都没有的旧任务为 `unowned`（显示为「未归属的任务」）。
- 段内 id 用 `encodeURIComponent`。未知页面回落到 `#/tasks`；未知 id 保留在 URL 中，由页面显示「未找到」空态并给出返回动作，不静默跳走。
- 跨页跳转一律生成路由链接（`<a href>`），可在新标签打开；不用回调在组件间传递「请求打开某任务」。
- 筛选条件、折叠状态等视图偏好继续存 localStorage，不进 URL。

### 3.3 页面骨架

所有页面共用一种骨架：

```
PageHeader（标题 + 一句 tips + 唯一主操作）
MetricStrip（可选：3–5 个对象级指标，点击即筛选）
┌───────────────┬──────────────────────────────┬──────────────────┐
│ 列表窗格       │ 主窗格                        │ 检查器（可选）     │
│ 搜索 + 筛选    │ 选中对象的全部内容             │ 二级对象的细节     │
│ 分组列表       │                              │                  │
└───────────────┴──────────────────────────────┴──────────────────┘
SaveBar（仅有未保存草稿时出现，贴底）
```

- 页面主体占满视口剩余高度；每个窗格各自滚动，页面本身不滚动。
- 页头标题 20px / 600，描述不再写在正文：用 `TitleWithTips` 的提示承载。
- 窗格之间用 1px `colorBorderSecondary` 分隔，不加阴影、不加卡片外框；窗格背景 `colorBgContainer`，画布 `colorBgLayout`。
- 设置页没有可选对象，只用「分组设置行」骨架（§4.6）。

### 3.4 响应式

| 视口宽度 | 布局 |
| --- | --- |
| ≥ 1440 | 三栏：列表 320 · 主窗格自适应 · 检查器 480 |
| 1024–1439 | 两栏：列表 280 · 主窗格；检查器以右侧抽屉（宽 560）覆盖主窗格 |
| < 1024 | 单栏堆叠：列表 → 主窗格 → 检查器逐级进入，顶部显示「返回」；导航收进抽屉 |

任何宽度都不允许出现横向滚动条或被截断的操作按钮。

## 4. 页面

### 4.1 工作台（任务）

页头：标题「工作台」，主操作「新建任务」；右侧视图切换 `Segmented`：「看板」「会话」「全部任务」，默认「看板」。三个视图回答不同问题：看板＝现在各状态有什么（全局一眼看清），会话＝某个父 Agent 会话推进到哪，全部任务＝查历史。

**看板视图（默认）**

- 四列：待执行（queued / scheduled / draft）· 执行中（running / cancelling）· 待验收（completed 且验收待定）· 已结束（已通过、需修改、失败、已取消）。列宽均分，列内各自纵向滚动（虚拟列表），滚动条常驻（`scrollbar-gutter: stable`），展开折叠不引起宽度跳动。
- 列的区分只用整列纵向浅底色：待执行灰、执行中蓝、待验收琥珀、已结束最浅灰；列头用状态文字色显示「标签 · 数量」。列顶不加强调色细线或边框。
- 列内按工作目录分组：组头 = 目录名 + 数量，悬停显示完整路径；每组都显示组头（含只有一组时，因为卡片上不再显示目录）；组按最近更新倒序，组可折叠，折叠状态存 localStorage。待执行、执行中、待验收默认展开；已结束默认折叠，只显示组头与数量。
- 已结束列只放近 24 小时内结束的任务；列底显示「更早的任务在全部任务中查看」链接到 `#/tasks/all`。
- 卡片：第一行状态/健康徽标 + 标题（最多两行）；第二行子 Agent 芯片（引擎图标 + profile）；底部一句话：「由 <宿主> 于 HH:mm 派发 · 最新上报 HH:mm」，已完成或待验收时后半句为「完成于 HH:mm」（宿主只取实例名首段，悬停显示完整名，时间今天 HH:mm、其他日期 MM-DD HH:mm，悬停给完整时间）。关注集合（§5.2）中的卡片在右上角显示 warning 标记；置顶的卡片排在组内最前并显示置顶图标。
- 看板上方只有一行工具条：搜索（任务标题、子 Agent、工作目录）+ 工作目录多选 + 父 Agent 多选；有筛选时显示「清除筛选」。不再用多行筛选芯片。
- 点击卡片：URL 变为 `#/tasks/t/<id>`，任务检查器（§4.2）以右侧覆盖层（宽 560）打开，看板保持原宽不重排；Esc 或关闭按钮收起，焦点回到原卡片。
- < 1024：看板改为单列，列头位置换成状态 `Segmented`（待执行 / 执行中 / 待验收 / 已结束，带数量），检查器全屏进入并有「返回」。

**会话视图**

- **列表窗格：会话列表。**
  - 顶部：搜索框（匹配会话标题、任务标题、子 Agent、工作目录），时间范围 `Select`（今天 / 近 24 小时 / 近 7 天 / 近 30 天 / 全部，默认近 24 小时，按会话最近活动时间），范围 `Segmented`：需关注 / 进行中 / 全部（默认「进行中」，「需关注」带计数）。
  - 按工作目录分组：组头显示目录名 + 会话数，悬停显示完整路径；每组都显示组头（含只有一组时），组按最近活动倒序。
  - 会话行（两行，高 56）：第一行 = 宿主引擎图标 + 会话标题（单行省略）+ 右侧最近活动时间；第二行 = 任务状态计数（如「2 执行中 · 1 待验收 · 4 已通过」，只列非零项，执行中用 processing 色点）+ 关注标记（会话内有关注集合中的任务时，行尾显示 warning 图标与数量）。
  - 会话标题取值顺序：会话目标标题 → 实例 `title` → 「宿主 · HH:mm」。不显示完整实例名（`<Host> · <workspace> · <HH:MM>`）。
  - 排序：关注集合中的会话在组内置顶，其余按最近活动倒序。
  - 键盘：↑/↓ 移动，Enter 打开，`/` 聚焦搜索。

- **主窗格：会话详情。**
  - 头部：标题、会话类型标签（「网页发起」/「宿主会话」）、父 Agent（引擎图标 + profile）、工作目录（可复制）、开始时间；会话目标的操作按钮（开始执行 / 编辑 / 取消 / 接续）放在头部右侧。
  - **进度汇报区**（仅会话目标有）：`ownerReport` 的摘要、`Progress` 百分比、阶段、阻塞项（warning 色列表）、下一步、汇报时间；汇报超过 15 分钟未更新时在时间旁标注「已过期」。没有汇报时显示「父 Agent 尚未汇报进度」。
  - **会话目标区**（仅会话目标有）：目标与验收标准，默认折叠为 4 行，可展开。
  - **任务列表**：按「需关注 → 执行中 → 待验收 → 待执行 → 已结束」分段，每段一个小标题 + 计数，已结束段默认折叠。任务行（两行）：状态徽标 + 标题；第二行 = 子 Agent 芯片 · 当前活动（执行中时取最新事件，单行省略）或结果 · 「HH:mm 派发 · 最新上报 HH:mm / 完成于 HH:mm」。重试链：重试任务缩进挂在原任务下，标注「第 N 次尝试」；被替代的任务显示「已被替代」并链接到替代者。
  - 未选中会话时：主窗格显示全局概览——MetricStrip（执行中 / 排队中 / 需关注 / 今日完成）+ 最近需关注的任务列表（最多 10 条）。

- **检查器：任务详情**（§4.2）。

**全部任务视图**

- 一张虚拟滚动表格替代原「归档」抽屉和看板筛选：列为 状态 / 任务 / 会话 / 子 Agent / 工作目录 / 结束或最近上报。
- 表头上方一行筛选：搜索、时间范围、状态（多选）、父 Agent、子 Agent、工作目录（多选 `Select`）。筛选维度与会话视图一致。
- 行点击在检查器打开任务；URL 为 `#/tasks/all/t/<id>`。检查器打开时表格收为两行式任务列表（状态+任务 / 会话·工作目录·时间），避免六列在剩余宽度内被截断；关闭检查器恢复表格。

### 4.2 任务检查器

替代原七标签详情抽屉。结构固定：

1. **头部**：标题（可换行）；状态徽标（solid）+ 健康徽标；操作按钮（验收 / 编辑 / 开始执行 / 取消 / 新建重试）；关闭按钮。
2. **状态横幅**（固定位置，按需出现）：排队原因、失败原因（失败类别 `failure.kind` 的中文名 + 恢复建议 + 可复制的错误详情）、已取消、已被替代。这是业务状态内容，不是错误弹窗。
3. **标签页**（`PageTabs`）：
   - 概况：当前活动 / 执行结果摘要；事实清单（`Descriptions`：子 Agent、模型、会话、工作目录、派发时间、更新时间、重试来源链接）。
   - 时间线：沿用现有事件折叠规则，顶部搜索。
   - 结果与验收：交付状态、验收结论、验收说明、产物列表（合并原「产物」「验收」两个标签）。
   - 要求：执行约束、验收标准、Prompt（Prompt 折叠，可复制）。
4. 「接续」不再是任务的标签页，移到会话头部的「接续」操作。

### 4.3 父 Agent / 子 Agent

主从骨架：

- 页头主操作「新建父 Agent / 新建子 Agent」；MetricStrip：启用 / 可派发 / 被引用 / 已暂停。
- 列表窗格：拖动手柄排序（保存后生效）；行 = 启用开关 + 引擎图标 + id + 状态徽标（可用 / 已暂停 / 渠道停用…）；第二行 = 渠道 · 模型。
- 主窗格（编辑器）按 `Section` 分段：基本（ID、账号或渠道、模型、推理强度）→ 调度（并行上限、子 Agent 权重 / 并发上限、免费渠道）→ 可用性（连通测试、免费渠道探测、暂停状态与恢复）→ 关系（被哪些父 Agent / Bot / 定时任务引用、最近 5 个任务，全部为链接）。
- 每段的解释文字进 `TitleWithTips`，字段下方只保留一行必要提示。
- 编辑走草稿 + SaveBar；启用开关、删除、恢复派发是即时操作（§6）。

### 4.4 账号与渠道

与 §4.3 相同的主从骨架：

- 页头主操作「添加账号」，次操作「导入」；MetricStrip：账号与渠道 / 官方订阅 / API / 额度可用。
- 列表窗格：类型与引擎筛选；行 = 启用开关 + 引擎图标 + 名称 + 额度状态点；第二行 = 类型 · 引擎 · 额度摘要（如「7 天 已用 22%」）。额度耗尽或未登录的行在第二行用 warning / error 文本。
- 主窗格：头部（名称、类型标签、启用开关、登录、删除）；分段：凭据、额度（窗口进度条、重置时间、观测时间、自动刷新开关、刷新按钮）、配置（编辑表单，草稿 + SaveBar）、关系（被哪些父 Agent / 子 Agent / Bot 引用，链接）。
- 登录与导入保留为 Modal（它们是一次性流程）。

### 4.5 定时任务

主从骨架：列表行 = 启用开关 + 名称 + 类型标签 + 下次运行时间 + 最近结果徽标；主窗格 = 配置（草稿 + SaveBar）+ 运行历史（内嵌列表替代原抽屉，「在工作台查看」为路由链接）。保留 commandId 核对机制。

### 4.6 Bot 与设置

- 共用 `SettingGroup` / `SettingRow`：左侧标签 + `TitleWithTips` 提示，右侧控件；分组标题在组的上方而不是左侧第一列。
- Bot：顶部连接状态卡（连接、Agent 状态、会话数、最近消息时间、操作），下方设置分组，草稿 + SaveBar。
- 设置：逐项即时生效，行内显示「保存中 / 已保存」。

## 5. 视觉规则

### 5.1 表面与几何

- 只用 `cssVar` token；颜色、圆角、阴影、字体不写裸值。间距取 4 / 8 / 12 / 16 / 24。
- 层级：画布 `colorBgLayout` < 窗格 `colorBgContainer` < 浮层（Modal / Drawer / Popover，带阴影）。窗格和列表行不加阴影。
- 选中行：`colorFillSecondary` 背景 + 左侧无装饰条；悬停：`colorFillTertiary`。不使用 3px 强调条、渐变、玻璃态。
- 圆角：窗格内控件 `borderRadius`；浮层 `borderRadiusLG`。
- 字号：页标题 20/600，窗格标题 16/600，段标题 14/600，正文 `fontSize`，元信息 `fontSizeSM` + `colorTextSecondary`。计数、时间、百分比用等宽数字。

### 5.2 状态色与关注集合

唯一事实源 `src/renderer/format/status-colors.ts` + `tag-colors.ts`。任务显示状态与色调不变：

| 状态 | 文案 | 色调 | 图标 |
| --- | --- | --- | --- |
| draft | 草稿 | 中性 | — |
| queued | 待执行 | 中性 | — |
| scheduled | 排队中 | 中性 | — |
| running | 执行中 | processing | 旋转 Loader |
| cancelling | 停止中 | orange | 旋转 Loader |
| review | 待验收 | warning | — |
| accepted | 已通过 | success | — |
| rejected | 需修改 | volcano | — |
| failed | 失败 | error | — |
| cancelled | 已取消 | 中性 | — |

**关注集合**（导航角标、「需关注」范围、会话置顶共用一个判定函数 `needsAttention(task, now)`）：

- 失败且未被重试或替代的任务（同一重试链只算最新一次）；
- 需修改且未被重试的任务；
- 待验收等待超过 30 分钟的任务。

任务列表数据不含健康状态（`tasks.health` 只在检查器里按任务轮询），因此「停滞」不进关注集合，只在检查器头部的健康徽标里显示。

列表里状态用「色点 + 文字」，检查器头部用 solid Tag；不只靠颜色表达状态。

### 5.3 身份

- 引擎图标（`@lobehub/icons`）始终在 Agent 名称前，组成「Agent 芯片」：图标 16 + 名称单行省略 + 悬停完整名。
- 父 Agent 身份紫色、子任务身份 geekblue、免费渠道 cyan——与状态色互不重叠（沿用 tag-colors）。
- 会话与工作目录用 lucide 图标（`MessagesSquare` / `Folder`），不用 emoji。

### 5.4 时间

所有时间经 `TimeText`：当天 `HH:mm`，其他日期 `MM-DD HH:mm`，悬停显示完整时间与时区；时间线额外显示相对时间。不再使用无悬停的纯文本时间。

### 5.5 动效

- 检查器进入 200ms ease-out、离开 150ms ease-in，只动 `transform` / `opacity`；列表悬停 150ms。
- 状态变化不做动画；执行中只用 Loader 旋转。
- 尊重 `prefers-reduced-motion`：关闭位移，只保留淡入。

## 6. 交互模型

### 6.1 保存

| 类型 | 适用 | 行为 |
| --- | --- | --- |
| 草稿 + SaveBar | 父/子 Agent 编辑、渠道配置、定时任务配置、Bot 配置、任务编辑 | 修改即进入草稿；窗格底部贴出 SaveBar「有未保存的修改 · 放弃修改 · 保存」；切换选中对象、离开页面、关闭浏览器前若有草稿则确认；保存失败保留草稿并在字段上标错 |
| 即时 | 启用开关、删除、恢复派发、刷新额度、连通测试、立即探测、定时任务运行/停止、设置页单项 | 点击即提交；控件进入 loading，成功后就地更新，失败用 toast 说明原因并恢复原值 |

父/子 Agent 共用同一份策略草稿，SaveBar 显示「N 个 Agent 有未保存的修改」。

### 6.2 反馈

- 请求错误、连接问题一律浮层：`toast`（右下角）。瞬时断连显示旋转的「正在重新连接…」并自动重试，用户不需要点重试。
- 字段校验错误留在字段下方；持久业务状态（任务失败原因、Agent 已暂停）是内容，放在固定位置（检查器状态横幅、编辑器头部）。
- 写操作从不自动重放；传输失败后重读状态，告诉用户操作是否生效。
- 破坏性操作二次确认，文案写清对象和后果（「删除渠道 X 后，引用它的 2 个子 Agent 将无法派发」）。

### 6.3 加载与空态

- 首次加载：窗格内 `Skeleton`，形状贴近真实内容；后台刷新不出现骨架，也不让内容闪动。
- 每个空态说明原因并给下一步动作：无会话 →「新建任务」；筛选无结果 →「清除筛选」；未找到（URL 指向已删除对象）→「返回列表」。
- 失败与空不混淆：读取失败时保留上次内容，并在窗格内显示「读取失败 · 重试」的固定行（不插入页面流，替换内容区的占位）。

### 6.4 焦点与键盘

- 列表是 listbox：↑/↓ 移动、Enter 打开、Home/End 首尾；选中项 `aria-selected`。
- Esc 关闭检查器并把焦点还给触发它的列表行；行已不存在时回到列表搜索框。
- `/` 聚焦当前页搜索框（输入框内不拦截）。
- 打开 Modal / Drawer 时焦点进入浮层，关闭后回到触发元素。

## 8. 验收清单

每个页面交付前在真实浏览器（1440×900、1280×800、1024×768、390×844）逐项确认：

1. 首屏能指出唯一主操作；一屏 primary 按钮不超过 1 个。
2. 无横向滚动、无被截断的按钮、无重叠；长标题单行省略且悬停可见全文。
3. URL 反映当前选中对象；刷新后回到同一处；后退回到上一个选中对象。
4. 空态、加载、读取失败、未找到四种状态都有正确文案和下一步动作。
5. 键盘可完成：列表移动、打开、Esc 关闭、焦点回到原行。
6. 术语与 §2 一致；无「负责人 / 工作代理 / 思考力度 / 工作空间」。
7. 只有一套状态色；颜色之外有文字或图标。
8. 有草稿时 SaveBar 出现，切换对象会确认；即时操作有 loading 与结果反馈。
9. 控制台无报错，网络面板无失败请求（预期的 404 / 校验失败除外）。
10. 仅要求亮色主题。
